# Art guide — replacing the graphics

Every image in *One More Credit* is generated by code and **designed to be
thrown away**. This document is the contract: follow it and any sprite or
background can be replaced without touching a line of TypeScript.

---

## The two rules that matter

Everything else here is detail. These two rules are what make the game look
like one coherent object rather than a pile of assets:

### 1. Author at the target resolution

The game renders at **320 × 200** and integer-scales up. A character is 24 × 40
pixels. An inventory icon is 16 × 16.

Do **not** draw at 1024 × 1024 and shrink it. Downscaling a detailed image
produces anti-aliased mush — hundreds of intermediate colours, soft edges, no
readable silhouette. It reads as *a shrunken photo*, not as pixel art. This is
the single most common way retro-styled games look wrong.

If you have a high-res source anyway (an AI generation, a photo, a painting),
run it through the quantiser, which box-downsamples *before* reducing colours:

```bash
node tools/quantize.mjs my-render.png --sprite char.jack
```

### 2. Use only the locked palette

All 32 colours live in `src/content/palette.json`. Nothing else is legal.

This is not a stylistic preference — it is the mechanism that makes art from
different sources, different tools and different days look like it belongs to
the same game. It is why 1980s games are visually coherent and why modern indie
pixel art often is not.

`art-templates/_palette.png` is a swatch sheet you can load directly as a
palette in Aseprite, GraphicsGale, Pro Motion, Photoshop or GIMP.

**Alpha is binary.** A pixel is either fully opaque (255) or fully transparent
(0). Partial alpha produces halos when the image is scaled up 5×.

## Quick start

```bash
npm run assets:placeholders   # writes drawing templates to art-templates/
# ...draw...
npm run assets:validate       # checks everything against the manifest
```

The templates are the exact final pixel size with:

- **purple dotted lines** — frame boundaries
- **magenta crosses** — the sprite's anchor point (where it touches the floor)

Draw over the guides, delete the guide pixels, save into
`public/assets/sprites/` under the filename the manifest expects (drop
`.template` from the name).

## Replacing a sprite

Game code never names a file. It asks for a logical id — `char.jack` — and the
mapping from id → file → frame grid lives entirely in
`public/assets/sprites/manifest.json`.

### Same dimensions (the common case)

Drop a PNG into `public/assets/sprites/` with the filename and exact pixel
dimensions the manifest declares. **That is the whole process.** No rebuild, no
code change. Reload the page.

To find the required size:

```bash
npm run assets:validate
# ---- char.maggie
#      no art yet - needs maggie.png at 144x160 (6x4 frames of 24x40)
```

### Different dimensions

Edit that sprite's entry in `manifest.json` — it is the only place geometry is
defined:

```jsonc
"char.jack": {
  "template": "person",
  "file": "jack.png",
  "frameWidth": 32,      // ← override anything from the template
  "frameHeight": 52,
  "anchorX": 16,
  "anchorY": 52
}
```

Then re-run `npm run assets:placeholders` to get a fresh template at the new
size.

### Character sheet layout

Human characters use the `person` template: **6 columns × 4 rows of 24 × 40**
(144 × 160 total).

| Row | Contents |
|-----|----------|
| 0 | Facing camera — cols 0–3 walk cycle, cols 4–5 talk loop |
| 1 | Facing **right** — same layout |
| 2 | Facing away — same layout |
| 3 | Expressions: surprised, annoyed, happy, frightened, worried, smug |

Column 0 of rows 0–2 doubles as the standing pose.

**You never draw the left-facing row.** The engine mirrors the right-facing row
automatically. Keep asymmetric details (a badge, a parting) subtle, or they will
flip.

The **anchor** is bottom-centre: `(12, 40)`. That point is where the character
stands on the floor. Get it wrong and the character floats or sinks.

### Inventory icons

16 × 16, single frame, one file each. Leave a pixel of padding all round so the
icon does not touch the inventory slot border.

## Replacing a background

Backgrounds are **320 × 200** PNGs in `public/assets/backgrounds/`, named after
the scene's `background` id (`pier.png`, `arcade_floor.png`, …).

Drop the file in and it takes over from the code painter automatically. Delete
it and the painted version comes back. There is no manifest entry to edit and
no registration step.

**Compose for the top 144 rows.** The verb/inventory panel covers everything
below y=144 during play. Paint the full 200 rows anyway — the title screen and
cutscenes use the whole frame — but nothing important goes in the bottom 56.

`art-templates/_background.template.png` marks the 144 line for you.

The full list of background ids is in `src/content/backgrounds.ts`.

## The validator

```bash
npm run assets:validate
npm run assets:validate -- --strict   # also fail on warnings
```

It checks, for every file:

- the file exists and is a readable PNG
- pixel dimensions exactly match `columns × frameWidth` by `rows × frameHeight`
- **every colour is in the palette** (and names the offenders with pixel counts)
- alpha is strictly 0 or 255
- no animation references a blank frame — which almost always means the frame
  grid is miscounted

Missing art is reported but is **never an error**: the game generates a
correctly-sized, palette-correct, actually-animating placeholder for anything
absent. You can ship, playtest and tune timing with zero art on disk, and add
finished sprites one at a time.

## The quantiser

```bash
# Fit a high-res image to a sprite's exact sheet size
node tools/quantize.mjs render.png --sprite char.maggie

# Fit to a background
node tools/quantize.mjs painting.png --background --out public/assets/backgrounds/pier.png

# Arbitrary size
node tools/quantize.mjs thing.png --size 24x40

# Fix colours only, leave the size alone
node tools/quantize.mjs public/assets/sprites/jack.png --in-place --no-resize
```

Dithering (`--dither floyd|ordered|none`):

- **floyd** (default) — Floyd–Steinberg error diffusion. Best for backgrounds
  and anything with gradients: skies, sea, lighting.
- **ordered** — a fixed 4 × 4 Bayer pattern. More obviously "retro", stable
  under animation, and the right choice for sprites, where error diffusion makes
  neighbouring frames shimmer.
- **none** — flat nearest-colour. Best for hard-edged graphic work, UI and logos.

## Working with generated art

The pipeline is built to make this practical, so a few things worth knowing:

- **Generate large, quantise down.** Ask for a clean, high-contrast image with a
  clear silhouette against a plain background, then let the quantiser handle the
  reduction. Detail below about 4 real pixels will not survive, so do not ask
  for it.
- **Silhouette first.** At 24 × 40 a character is read entirely by outline. If
  you cannot identify them from a solid black shape, no amount of interior
  detail will save it.
- **Expect to touch up.** Quantised output is a strong starting point, not a
  finished sprite. Eyes, hands and any single-pixel feature will need fixing by
  hand — but you are fixing 20 pixels, not drawing 1,000.
- **Do the sheet as one image.** Generating frames separately gives you a
  character whose proportions and colours drift between frames. Generate or draw
  the whole 144 × 160 sheet together.
- **Never** commit art you do not have the rights to. The whole game is original
  by construction — the palette, the music and every painted background are
  generated from code in this repository.

